# Memory, context and recovery

Proposed, 2026-10-02. Current journal checkpoints are not resumable task snapshots. This design keeps different kinds of state distinct.

## State categories

| Category | Authority and lifetime | Model exposure |
| --- | --- | --- |
| Durable project knowledge | Reviewed facts/decisions, versioned and scoped | Selected relevant entries with provenance |
| Task state | Goal, plan, status, budgets, child links, pending actions | Current task snapshot |
| Conversation transcript | Sanitized typed messages/tool-call linkage | Selected/reduced conversation, not full automatic replay |
| Model context | Derived prompt/template/tool schemas/media selection | Exact bounded request sent to one model |
| Tool results | Bounded text plus artifact refs, hashes, timestamps | Relevant excerpts, untrusted data annotations |
| Checkpoints | Consistent state revision and recovery boundary | Input to local recovery, not arbitrary prompt instructions |
| Remote KV cache | Engine-owned optimization, disposable | Never authority or a required persistence mechanism |

Compaction is a derived context artifact, not a fact promotion. A session restart does not promise preserved GPU cache. User instructions and permission policy remain separate from summaries generated by a model.

## Storage proposal

```text
workspace/.freecompute/
  knowledge/
    INDEX.md
    DECISIONS.md
    ARCHITECTURE.md
    PROJECT_STATE.md
    TASK_SUMMARIES/       # only promoted summaries
    entries/             # optional focused records as growth warrants

user-local-app-data/FreeCompute/workspaces/<workspace-id>/
  state.sqlite
  artifacts/
  snapshots/
  memory-proposals/
  logs/                  # bounded and sanitized
```

Do not create these now. Runtime state belongs outside the synced OneDrive working tree by default. Reviewed project knowledge may be version-controlled by explicit user preference; do not blanket-ignore all curated knowledge or automatically commit it. Global preferences/knowledge have separate user scope, never automatically shared with a project or worker. Canonical workspace identity must handle moved roots explicitly, not silently merge different repositories.

Legacy `.qwen_harness` data should remain untouched until an approved, versioned importer exists. Import it read-only, validate schema/path/content, preserve provenance, back up original data, and never infer approvals from old text logs.

## Controlled promotion

1. Agent or user proposes a knowledge delta with statement, scope, evidence references, source revision, confidence, review/expiry date, and rationale.
2. Local service checks sensitive content, duplicate/conflicting facts, trust source, and stale evidence. Inferred claims remain labeled.
3. User sees an exact diff against the current knowledge version. Default promotion requires explicit approval; no model can write trusted knowledge via a normal file tool.
4. Promotion uses expected-version/hash checks, records reviewer/decision/provenance, and preserves prior versions. Conflicts reopen review rather than last-writer-wins.
5. Retrieval selects by scope/relevance/freshness/trust, includes short citations, and never elevates task summaries or web pages into system policy.

A deterministic low-risk promotion policy might later permit mechanically verified facts, but only after the user approves its exact scope. Automatic freeform agent edits to durable knowledge are excluded. Revocation/deletion updates retrieval and indexes; sensitive-data deletion must consider artifacts, backups, and published Git history separately.

## Retrieval

Begin with Markdown index plus SQLite metadata/full-text search, stable entry IDs and path/symbol search. Add embeddings only when measured retrieval failures justify them. An embedding model is its own operation/worker/license/privacy decision. Cache indexes by file hash and model/version/dimension; never mix incompatible vectors.

Use repo-map/symbol retrieval plus targeted reads for code. Documents/web/tool output are untrusted inputs; label source and instruction trust rather than concatenating them into privileged policy. File excerpts carry path and content hash so the agent knows whether later edits target the same content.

## Context construction and prefix stability

Build a versioned stable prefix per model/agent/permission profile: system rules, sorted schema definitions, and fixed catalog metadata. Select tools/skills at a defined boundary; version changes deliberately invalidate prefix/cache affinity. Load full skill bodies/resources lazily into a task appendix rather than mutating the prefix on every turn. Permission restrictions are enforced locally even if schemas remain stable.

Budget the rendered model template, selected knowledge, tool schemas, media costs, transcript, tool results, and reserved output. Use the correct tokenizer or engine token-count endpoint when available. If only estimates exist, keep conservative margins and label them. Configured 65,536 tokens do not prove safe request length or per-slot capacity.

Keep current user goal, hard constraints, pending tool/approval linkage, unresolved decisions, recent edits and evidence during reduction. Prune redundant output; store large results as artifacts; summarize older turns with source references and recent tail. Summarization itself consumes a scheduled inference request and task budget. Never summarize away pending approval arguments or split tool-call/result pairs.

Handle `length` as truncation, not completion. Do not execute tools from truncated or malformed messages. Reasoning retention is profile/provider-specific; do not assume raw hidden reasoning is needed for recovery or safe to persist. Prefer concise task summaries.

Cache opportunities depend on exact prefix/template bytes, slot affinity, model version, compaction and load changes. Multi-agent slot churn can evict caches. Measure cached tokens/prefill rather than promising 100% reuse or sub-second TTFT.

## Checkpoint and recovery contents

A checkpoint references schema version, task/session revision, ordered transcript/artifact positions, agent/model/prompt/tool-schema versions, budgets/usage, pending inference/children/tool intents, approval scopes/expiry, workspace hashes, known worker boot/lease state, and latest knowledge version. Store immutable checkpoint references transactionally with authoritative state. Secret values are never serialized as config.

On restart: acquire core ownership, load latest compatible state, validate workspace identity, invalidate stale grants where required, reconcile unresolved effects, recheck workers/leases, rebuild bounded context, then offer resume. Unknown schema versions fail clearly; migrations require backups and explicit compatibility tests.

| Interrupted point | Recovery behavior |
| --- | --- |
| Before inference dispatch | Requeue if budgets/deadline/policy still permit |
| During stream | Retain sanitized partial text, mark attempt incomplete, reconcile request; no partial tools |
| Waiting approval | Reissue exact still-valid proposal or request a new review after drift |
| Before file replacement after intent | Compare hashes, then classify unapplied/applied/conflicted |
| During shell/MCP side effect | Mark uncertain; inspect evidence or ask user; never blind replay |
| After result commit before UI delivery | Replay committed event, do not re-execute |
| Worker expired | Retain task; wait or propose an already permitted alternative route |

Exactly-once external effects are not guaranteed. Crash-safe bookkeeping and explicit uncertainty are achievable; that is the acceptance target.
